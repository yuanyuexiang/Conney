## 交付规则与开发验收

规则基线日期为 2026-11-24。证据来自本地样本目录下的[收到的原始表格](../samples/edi/EDI项目所需表格/收到的原始表格/)和[整理后呈现的表格](../samples/edi/EDI项目所需表格/整理后呈现的表格/)。库内自动化测试使用脱敏副本及人工核对的预期结果。ZF 和博世是扩展样本，纳入交付需另行确认范围。

### 物料匹配与来源追溯

1. 一张映射表维护客户、客户料号、适用的订单号、订单行或收货方、康尼料号及交付需要的图号、包装和安全库存参数。客户和客户料号必填，额外匹配条件按模板使用。无匹配或多匹配时进入待核对。
2. 料号、订单号和报文编号按文本保留原值与前导零。DRX 原报文订单号 `000000311173` 可以按该客户的匹配规则与整理表 `311173` 对照。康尼料号 `40050030027500` 同时对应 DRX 的 `B1100740 / 311173` 与科伯舒特的 `01029077 / 10905505`，按客户范围维护这两条映射。
3. 每次生成记录来源附件、报文编号和日期、工作表与单元格、使用的匹配和交付规则。保留原始值、规则计算值和最终交付值。人工提供的分配、调整或厂内数据随结果记录来源。
4. 保留有效日期、区间、特殊日期和缺失日期的区别。无来源记录留空，显式零保留。保留数量类型和原单位，未知代码进入待核对，按已验证的类别计算需求。
   科伯舒特和 JLR 的六位日期在草稿中按报文日期的近世纪换算，原值和坐标随结果保留。报文日期用邮件收件日定位世纪，超出核验范围的日期进入待核对。
5. 原表提供的客户料号、订单、订单行、收货方和供应商料号可导入待匹配列表。科伯舒特使用原表的客户工厂作为收货方条件，Vitesco 使用框架订单号。ZF 从「交付明细」提取物料信息。原表没有提供的字段留空，管理员补录康尼料号后生成正式映射。相同匹配范围及供应商料号保留最新报文的来源。
6. 康尼料号和康尼图号以整理后的交付表和已核实的物料参考表为依据。整理表包含买方料号和采购订单时，用两项定位记录，再核对可用的供应商料号。只有采购订单时，须在同批原报文中唯一定位物料块，并核对其他期的匹配结果。缺少对应关系的记录继续待匹配。

### 科伯舒特 4905

- 以订单号和买方料号为行，支持按实际交货日汇总和按 ISO 周汇总。周表按周一归集，支持连续周列。通过所选交付模板确定列轴。发货日按 `ETD = ETA − 98 天` 计算，W45 的月小计按 ETD 所在月归集。
- `000000 / 0` 是样本中的零量占位，保留原始记录，排除在需求日期列之外。`333333` 保留代码和数量，在无有效日期的区域单列。W46 标注「未确定交货日期」，W47 标注「立即」，是否触发发货动作待业务确认。
- 原始传输号 `00052 / 00054 / 00056` 分别对应 `科伯舒特W45需求.xlsx`、`科伯舒特W46需求.xlsx`、`科伯舒特W47需求.xlsx`。三期有日期数量分别核对 150、142、116 条，均吻合，合计分别为 432,516、421,032、404,252 ST。W46「说明与校验」记录连续 ISO 周口径。W47「按交货日期汇总」和「明细」保留实际日期，另有 7 条 `333333`，合计 30,120 ST。

- 已核对 W45「交货计划转置」`A4:B43`、W46「交货预测周表」`A3:B43` 和 W47「按交货日期汇总」`A3:C38`，三期的采购订单均在同批原报文中唯一，W47 同时核对买方料号。三期去重后入库 41 条正式映射。

### 捷豹路虎 DELFOR 与 DELJIT

- DELFOR 按客户料号、采购订单和订单行归集。`QtyType=1` 按实际交货日归入对应周。`QtyType=3` 的首个累计周需求等于首个累计量减去 `PreviousCumulativeQty`，再扣除基准之后、首个累计周之前已计入的明细数量。后续用同一报文内的本期累计量减上期累计量。没有记录的周保留空白。周规则可据样本验收，月区间的分配口径待确认。
- 验收示例为 `JLR_DELFOR_0000000981341395_261122115153.xlsx` 和 `捷豹路虎Delfor总结11.23.xlsx`。订单 `5900004133` 的首个累计周为 2026-12-21，计算 `44,047 − 40,087 − 3,168 = 792`，对应 `Sheet2!BH24`。同表 11 月 30 日在汇总页为 576，在「给生产」为 1,440，作为原计算值与生产值的追溯用例。
- DELJIT 使用有交货日期的 `QtyType=1` 确定近期交货量。累计值和无日期数量单独保留。`JLR_DELJIT_0000000979100155_261109.xlsx` 的 768、912、96 对应 `捷豹路虎Delfor总结11.9.xlsx` 的三周需求，768 在样表拆为两笔 384。周内拆量和 DELFOR、DELJIT 对同订单、物料、交货周的取值优先级待确认。

- 已按买方料号和采购订单核对三期整理表的「给生产」与 `Sheet2` 中的 `D11:G11`、`D24:G25`，入库 3 条康尼料号及图号。

### 德科 DRX DELFOR

- 按客户料号和采购订单匹配，供应商料号辅助核验。包装字段可由主数据填入，每托数量为每箱数量乘每托箱数。保留原始要求交货日、日期区间、状态和数量类型。`QtyType=83` 与状态 `10` 的业务含义待确认。
- 已验证代码和单位的有效起止区间直接保留为区间预测。取得客户依据后，可补充区间内的具体交货日。有日期的已确认需求缺少运输信息时，列入「发货计划」的待安排列表。
- 待核对显示原因和原报文位置。管理员可对数量类型、状态和单位一致的待确认代码批量保存同一结论，也可逐条处理。核对结论、依据、操作人和时间随草稿保存，重新匹配时沿用，并写入导出的「需求与来源」。
- 运输方式和发货日已知时，常规空运 ETA 加 14 天，海运加 84 天。到货周沿用样表的 `YEAR` 和 `WEEKNUM(...,2)` 口径。手填 ETA、空海运切换周、欠交补发和跨周分配作为有来源的业务输入。
- 上述运输时效是 `drx-2` 基线。新发布的参数只自动用于新建草稿，重新匹配沿用草稿已锁定的参数。已有草稿可由管理员按 ETA 差异确认升级，原草稿版本、参数和工作簿可追溯。试算保留样本、解析版本和变更依据，手填 ETA 优先。
- 以 [德科需求.xlsx](../samples/edi/reference/德科需求.xlsx) 的「给生产」验证输出布局及包装、ETA、到货周公式。用 `德科-PLAN-客户-20261123.xlsx` 的「给客户」补充异常 ETA 与欠交回归，例如 `AI5 = 12800 + 8800`。整表数量以同批报文、匹配和调整数据齐备时的结果验收。
- 本地报文 259 已按「给生产」`C5:J16` 补录 12 条康尼料号。以客户料号和采购订单定位映射，并核对供应商料号。原报文的收货方 `4L` 随匹配范围保存。
- 报文 259 的 `B1100938 / 355023` 在 11 月 16 日和 23 日的「给客户」第 29 行均缺康尼料号。`B1101325 / 370439` 与 `B1100741 / 305680` 共用供应商料号，继续按各自的客户料号和订单核对。

### 舍弗勒 / Vitesco DELFOR

- 用 `EarliestDeliveryDate / LastDeliveryDate` 读取 `QtyType=113` 的交货区间。样本为周一到周日，按报表周次横向输出并保留零。库存公式为上期库存减本期预测，再加本期实际产量。期初库存、实际产量和产能使用厂内数据。
- 第 25 号报文的 2027 年 W6–W9 为 `0 / 10080 / 0 / 5040`，可在 `博世 舍弗勒需求2026.11.9.xlsx` 和 `博世 舍弗勒需求2026.11.16.xlsx` 的 `Sheet1!BA6:BD7` 验收。第 26 号报文已把 2027-02-08 那周改为 0，11 月 16 日成品仍为 10,080。生成时记录选用的报文，自动切换到新版本的口径待确认。库存公式可用后一份成品的「舍弗勒」页 `C2:G5` 验收。

- 整理表 `Sheet1!A7:C7` 提供 Vitesco 的康尼料号和图号，原表中的买方料号和框架订单号仍需业务确认对应关系。
