# Relay 项目工作地图

合同交付覆盖 Vitesco DELFOR、DRX DELFOR、JLR DELFOR、JLR DELJIT、Kroschu 4905。Vitesco 是第一条开发链路。已有五份原始附件保存在 `samples/edi/raw/`，用于结构核对，版本差异验收另需客户确认规则及同一计划的连续版本。

| 阶段 | 工作包与依赖 | 完成条件 | 状态 |
| --- | --- | --- | --- |
| 1 工程基础 | Python 和 Node 依赖锁、FastAPI、Next.js、PostgreSQL、Alembic、Compose 和 CI | 全新环境可启动；迁移完成后 API 就绪；通过入口访问前端和 API | 本地通过 |
| 2 首条采集链路 | 依赖 1。只读 IMAP、游标、附件归档、持久任务、Vitesco 解析、登录与原始记录查询 | 在本地重放重复及断线场景；客户邮箱授权后实连；Vitesco 样本 1 块、88 条、19 个零值，来源可追溯 | 本地回放、账号与权限通过，真实邮箱待实连 |
| 3 五模板与异常处理 | 依赖 2 的解析接口。先 DRX 验证重复物料块，再接 JLR 两模板和 Kroschu；补诊断、重解析和鉴权下载 | 逐文件核对 56 块、635 条及参考字段；重试、租约过期、旧 Worker 回写、异常定位均验证 | 五份样本已通过 Docker 归档、解析、鉴权查询和下载，重解析与异常后台待补齐 |
| 4 版本发布与差异 | 依赖 3 和逐模板确认的业务键、数量语义、版本顺序、连续版本样本 | 迟到、同编号冲突、未知代码、重新解析和并发发布均不误切当前版本；客户逐项核对差异 | 等待业务输入，可先开发规则无关部分 |
| 5 试运行与交付 | 依赖已确认上线范围、部署资源及前序验收。配置 HTTPS、权限、日志监控、备份和回退 | 在客户环境验证只读收件、容量和权限；独立环境恢复数据库及附件、核对哈希和追溯关系；交接运行手册 | 待开发 |

四周按合同条件起算。第一周优先搭建和验证采集，第二周推进五模板和查询，第三周按上线条件开展受控试运行，第四周复测、恢复演练和交付。开发阶段和客户验收阶段各自记录实际结果，容量和授权条件不足时按双方确认的安排调整。

| 客户输入 | 影响 | 现阶段可并行推进 |
| --- | --- | --- |
| 指定 263 账号、文件夹、TLS 接入与历史边界 | 真实邮箱采集和游标恢复验证 | 本地 IMAP 替身、MIME 文件重放、断线及 UIDVALIDITY 变化测试 |
| 五种模板的字段与代码说明、同一计划至少三个连续版本、业务验收人 | 计划发布、差异解释及验收 | 原始结构解析、异常诊断、规则无关的版本状态测试 |
| 云服务器、域名证书、处理规模、资源与备份位置 | 部署、容量及恢复验证 | 本地 Compose、迁移失败验证、部署和恢复脚本 |

每个工作包记录依赖、已验证行为、未验证场景及证据。完成原始结构解析后可查询来源。只有业务规则确认且记录通过校验，才可发布计划。
